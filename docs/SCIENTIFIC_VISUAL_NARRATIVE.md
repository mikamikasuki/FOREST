# Scientific architecture figures

Submission architecture figures default to a scientific argument: **problem
bottleneck → key mechanism or causal zoom → grounded consequence**. The mechanism
occupies the dominant visual area. Show the actual transformation, information
carried along dependencies, inputs, outputs and operating boundaries. A directory
of agents or an attractive row of generic boxes does not explain the contribution.
A structural arrow describes the method; empirical causal claims still require
the relevant intervention or ablation evidence.

Use an actual supplied example, symbolic state or faithful before/after
representation where it explains the intervention. Baseline structure can be
compared neutrally. Baseline failures, error examples and winning measurements
require their recorded evidence. Without an observed or sourced outcome, draw a
visibly labeled **Testable expectation** and state the experiment that would
discriminate it. Preserve negative evidence material to the scientific claim.
Charts and data tables remain actual data/vector renders.

The [sixteen-paper accepted corpus](PUBLICATION_REFERENCE_CORPUS.md) provides
recorded PDF pages, visual functions and experimental lessons. For example,
SWE-agent's introduction Figure 1 explains its agent-computer interface;
Tree of Thoughts' Figure 1 compares reasoning architectures; RAG's Figure 1 joins
retrieval and generation; Reflexion's feedback views connect the loop to task
evaluation. DSPy has no main-paper figure in this corpus: useful tables and clear
prose do not require decorative filler. These observations inform our narrative
design rule; they do not imply that every accepted paper uses the same three
panels, or that those papers establish a current project's scientific result.
Every project still imports topic-matched accepted peers.

`research.figures.narrative.story_design_request(context, mode)` builds the
evidence-bound storyboard request. The workflow makes and retains the actual
provider call, validates its JSON with `validate_storyboard`, then uses
`story_image_prompt` for actual image alternatives or an editable scientific
vector render. Assertions declare their status and actual source identities;
measured numeric statements bind `[[metric:ID]]` to supplied finite observations.
The structural validator does not certify scientific entailment.

Native `method` data contains `storyboard`, `story_context`, its complete
`mechanism.operations` as `nodes`, its actual `edges`, and
`narrative_mode: "scientific_story"`. PDF/SVG output retains the three layers,
operation details, dependency labels, inputs/outputs, boundaries and observed
metric units. Concise scientific transformations appear in the artwork; complete
assertions, rationale and experimental definitions remain in its editable source
and caption companion. The renderer wraps text using actual font widths within
declared physical dimensions. Content that cannot fit at 8 pt requires a wider
span or explicit separate panels. It never expands a paper figure into a poster
or silently truncates scientific content.

Evidence Reviewer, Figure Critic and Visual Editor receive actual candidates and
their scientific context and actual caption companions. All three independently assess unsupported statements,
mechanism clarity and readability at print size. No renderer invents their
verdicts. Selected original-resolution images go into the manuscript; compact
review previews do not replace them. Paragraph selection and actual compiled-page
checks verify where the asset finally appears.

An explicit simple method-diagram request uses `method_only`. It retains supplied
nodes, edges and exact labels, and needs no fabricated bottleneck, superiority
story or expected advantage. This individual figure choice does not reduce the
default full-submission experiment or manuscript workload.
