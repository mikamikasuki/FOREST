# Scientific architecture figures

Submission architecture figures default to a scientific argument: **problem
bottleneck → key mechanism or causal zoom → grounded consequence**. The mechanism
occupies the dominant visual area. Show the actual transformation, information
carried along dependencies, inputs, outputs and operating boundaries. A directory
of agents or an attractive row of generic boxes does not explain the contribution.
A structural arrow describes the method; empirical causal claims still require
the relevant intervention or ablation evidence.

Use an actual supplied example, symbolic state or faithful before/after
representation where it explains the intervention. Baseline structure can be
compared neutrally. Baseline failures, error examples and winning measurements
require their recorded evidence. Without an observed or sourced outcome, draw a
visibly labeled **Testable expectation** and state the experiment that would
discriminate it. Preserve negative evidence material to the scientific claim.
Charts and data tables remain actual data/vector renders.

The [accepted reference corpus](PUBLICATION_REFERENCE_CORPUS.md) provides recorded
PDF pages, visual functions and experimental lessons. Select topic-matched peers
for the current contribution. Their figures inform explanatory depth and visual
hierarchy; their results do not establish the current method's claims.

`research.figures.narrative.story_design_request(context, mode)` builds the
evidence-bound storyboard request. The workflow makes an actual provider call
and validates its JSON with `validate_storyboard`. Assertions declare their status
and actual source identities;
measured numeric statements bind `[[metric:ID]]` to supplied finite observations.
The structural validator does not certify scientific entailment.

Native `method` data contains `storyboard`, `story_context`, its complete
`mechanism.operations` as `nodes`, its actual `edges`, and
`narrative_mode: "scientific_story"`. PDF/SVG output retains the actual mechanism,
operation identities, dependencies, inputs/outputs, boundaries and observed
metric units. Concise scientific transformations appear in the artwork; complete
assertions, rationale and experimental definitions remain in its editable source
and caption companion. The renderer wraps text using actual font widths within
declared physical dimensions. Content that cannot fit at 8 pt requires a wider
span or explicit separate panels. It never expands a paper figure into a poster
or silently truncates scientific content.

## Editable production workflow

Provider-backed `method` and `image` rendering uses the same production pipeline:

1. Freeze the supplied operations, dependencies, claims and evidence in a scientific
   content contract. Organize the figure around the strongest supported contribution.
2. Design at least two distinct compositions, with a dominant mechanism view and
   useful local detail. Every panel must explain a scientific point.
3. Compile the complete source overview from its frozen nodes and dependencies.
   Source-bound semantic groups and a forward chain guide a layered layout.
   The host measures labels, places every operation and reserves separate
   feedback paths and label space before routing. The model designs the
   dominant mechanism and useful overview glyphs with native tensors, attention matrices,
   token interactions, geometry or bounded local drawing primitives. It does not
   recreate global IDs, source connections or page coordinates.
4. Generate isolated illustration assets only when needed. Labels, formulae,
   panels and arrows remain editable in this native composition stage.
5. Render SVG, vector PDF and a 300 dpi PNG at the actual manuscript dimensions.
   Pack ordered object groups using measured glyph and text dimensions; reserve
   headers and connection space. Measure type size, clipping, overlap and routes.
6. Have Evidence Reviewer, Figure Critic and Visual Editor inspect the actual
   candidate pixels against the complete source contract. Selection requires all
   three to accept, every score to reach four out of five, and all deterministic
   geometry checks to pass.
7. Repair the named elements that failed, render again and repeat within the
   configured iteration and spending limits. Preserve scientific content during
   every repair. Publish a passing native candidate when available.
8. If native composition exhausts its passes and an image model is configured,
   perform one final whole-image batch. Give the designer the complete scientific
   contract, theory and model context, graph, prior composition plans, actual
   candidate pixels and concrete defects. Request a polished scientific
   illustration suitable for a top-tier journal or conference. Generate five
   complete alternatives by default, review their actual pixels with the same three
   roles and select the best scientifically faithful image. This step adds no
   further repair loop.

The selected output includes editable SVG, PDF, PNG, a rerenderable Python entry
point, complete source data, scene JSON, style, caption context and final quality
metadata. Image components are embedded so copying the figure preserves them.
The final whole-image path instead delivers the original PNG and a PDF containing
that bitmap, with its source prompt, scientific data, caption and final review
metadata. Its labels and shapes are not individually editable. Source fidelity
and scientific coverage require an accepted Evidence Reviewer verdict. Visual
revisions may remain in a `best_available` selection; this is distinct from
passing the complete publication gate. Actual print resolution is recorded
without upsampling or invented font measurements.

Temporary designs, failed candidates and raw model replies are removed. If no
scientifically faithful candidate can be selected, the workflow returns the
remaining defects.

Short display aliases retain canonical labels and scientific identities. An arrow
can omit redundant text when its endpoints, ports or glyphs explain its meaning;
its complete source dependency remains recorded and subject to review. Capacity
failures trigger composition replanning. A regressed revision starts its next
repair from the better observed scene, with matching preview pixels.

`research.figures.production.produce_diagram` orchestrates the pipeline;
`research.figures.spec` validates content and scene bindings;
`research.figures.composition.compile_composition` builds the canonical overview
and assembles the source-bound local mechanism;
`research.figures.scene.render_scene` performs the actual rendering. The existing
figure creation, rendering and manuscript insertion calls use these components.
Empirical charts retain their existing measurement-backed renderers.

`config.figure_design_max_output_tokens` defaults to 12288; set it on the text
provider when a dense local mechanism needs more output space. `visual_review_attempts` controls the maximum
production passes. All actual text and image requests use the configured model
and existing spending controls.
`config.figure_raster_finish_candidates` defaults to five and accepts two to
five. The final batch requires `image_generation.model` and
`image_generation.max_request_usd`; native-only providers retain the native
workflow. Existing empirical charts are never replaced by this illustration path.

Selected original-resolution assets go into the manuscript; review previews do
not replace them. Paragraph selection and actual compiled-page checks verify
where the asset finally appears.

An explicit simple method-diagram request uses `method_only`. It retains supplied
nodes, edges and exact labels, and needs no fabricated bottleneck, superiority
story or expected advantage. This individual figure choice does not reduce the
default full-submission experiment or manuscript workload.
